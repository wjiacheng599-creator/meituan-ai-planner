## Phase 1: 数据一致性 Bug 修复（P0，预计 1-2 天）

### 1.1 bookedVariants 数据库列缺失导致数据永久丢失

**问题**: SQLite `plannerTaskStates` 表缺少 `bookedVariants` 列，但 `rowToTaskState` 尝试读取该字段，导致预订变体数据无法持久化。

**涉及文件**:
- [server/repository/sqliteRepository.ts](file:///Users/wujiacheng/Documents/Playground/meituan-ai-planner-competition/server/repository/sqliteRepository.ts)

**修改方案**:
1. 在 `CREATE TABLE` 语句中添加 `bookedVariants` 列:
   ```sql
   bookedVariants TEXT NOT NULL DEFAULT '[]',
   ```
2. 在 `addColumnMigrations` 中添加迁移:
   ```typescript
   "ALTER TABLE plannerTaskStates ADD COLUMN bookedVariants TEXT NOT NULL DEFAULT '[]'",
   ```

**验证**: 执行预订操作后，重启服务端，检查 `bookedVariants` 数据是否持久化。

---

### 1.2 双重 localStorage 持久化冲突

**问题**: `storage.ts` 使用 `meituan_planner_reset_v2_` 前缀读写，Zustand persist 使用 `meituan-planner-storage` key。启动时两边数据可能互相覆盖。

**涉及文件**:
- [src/services/storage.ts](file:///Users/wujiacheng/Documents/Playground/meituan-ai-planner-competition/src/services/storage.ts)
- [src/hooks/useAppBootstrap.ts](file:///Users/wujiacheng/Documents/Playground/meituan-ai-planner-competition/src/hooks/useAppBootstrap.ts)
- [src/store/appStore.ts](file:///Users/wujiacheng/Documents/Playground/meituan-ai-planner-competition/src/store/appStore.ts)

**修改方案**:
1. 统一使用 Zustand persist 作为唯一 localStorage 数据源
2. 将 `storage.ts` 的 `loadProfiles()`, `loadSavedPlans()`, `loadTaskSessions()` 等改为从 Zustand store 读取
3. 在 `useAppBootstrap` 中移除对 `storage.ts` 的直接调用，改为从 Zustand store 恢复
4. 保留 `storage.ts` 的写入函数作为 Zustand persist 的 fallback（兼容旧数据迁移）

**验证**: 启动应用后，检查 localStorage 中只有一个 key 存储数据，且数据完整。

---

### 1.3 服务端同步全量替换导致并发数据丢失

**问题**: `replaceProfiles` 和 `replaceSessions` 使用 DELETE ALL + INSERT ALL 模式，并发同步时后到的请求覆盖先到的。

**涉及文件**:
- [server/repository/sqliteRepository.ts](file:///Users/wujiacheng/Documents/Playground/meituan-ai-planner-competition/server/repository/sqliteRepository.ts)

**修改方案**:
1. 将 `replaceProfiles` 改为 `upsertProfiles`（使用 `INSERT OR REPLACE` 逐条 upsert，而非 DELETE ALL）
2. 将 `replaceSessions` 同理改为 `upsertSessions`
3. 添加 `lastUpdatedAt` 时间戳比较，只保留较新的数据

**验证**: 模拟两个标签页同时同步，检查数据是否完整。

---

### 1.4 同步防抖导致最后更新丢失

**问题**: useAppBootstrap 中 250ms 防抖，用户关闭页面太快时最后修改不同步。

**涉及文件**:
- [src/hooks/useAppBootstrap.ts](file:///Users/wujiacheng/Documents/Playground/meituan-ai-planner-competition/src/hooks/useAppBootstrap.ts)

**修改方案**:
1. 添加 `beforeunload` 事件监听，页面关闭前立即 flush 待同步数据
2. 使用 `navigator.sendBeacon` 发送同步请求（不阻塞页面关闭）

**验证**: 快速修改数据后关闭页面，重新打开检查数据是否同步。

### 3.2 优化状态管理：useState → useReducer

**目标**: Explore.tsx 中 38 个 useState 导致大量重渲染。

**方案**: 将相关状态合并为 useReducer：

```typescript
// 合并前：38 个 useState
const [searchQuery, setSearchQuery] = useState('');
const [searchResults, setSearchResults] = useState([]);
const [isSearching, setIsSearching] = useState(false);
// ...

// 合并后：按功能域分组的 useReducer
type SearchState = { query: string; results: POI[]; loading: boolean; error: string | null };
function searchReducer(state: SearchState, action: SearchAction): SearchState { ... }
const [searchState, dispatch] = useReducer(searchReducer, initialSearchState);
```

**分组建议**:
- `searchState` — 搜索相关（query, results, loading, error）
- `mapState` — 地图相关（center, zoom, markers, selectedMarker）
- `postState` — 发布相关（draft, media, publishing）
- `filterState` — 筛选相关（category, price, distance）

---

### 3.3 添加 useMemo/useCallback 优化

**关键优化点**:

1. **Explore.tsx 的 categoryConfig**: 使用 `useMemo` 包裹，避免每次渲染创建新对象
2. **Itinerary.tsx 的回调函数**: 将 `onClick={() => ...}` 内联回调提取为 `useCallback`
3. **ActivityTimeline 的排序数据**: 使用 `useMemo` 缓存排序结果

### 3.4 移除 console.log 残留

**方案**: 
1. 在 `vite.config.ts` 中添加 `esbuild.drop: ['console', 'debugger']` 用于生产构建
2. 保留 `console.warn` 和 `console.error` 用于错误追踪

```typescript
// vite.config.ts
esbuild: {
  drop: process.env.NODE_ENV === 'production' ? ['console', 'debugger'] : [],
  pure: ['console.log', 'console.debug'],
}
```
