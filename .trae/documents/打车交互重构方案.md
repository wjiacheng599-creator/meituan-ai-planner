# 打车交互重构方案

## 概述

### 目标
将打车（Taxi）功能从 Agent 一键执行流程中解耦，改为独立、直观的交互模式：
- 行程页交通卡片上增加「去打车」按钮，点击弹出底部叫车面板
- 首页快捷服务区域增加「去打车」胶囊按钮，支持自动填充目的地或手动输入
- 彻底移除 Agent 执行流程中的 `dispatch_taxi` 步骤

### 当前问题

| 问题 | 描述 |
|------|------|
| 打车与活动预订混在一起 | `travelMode === 'taxi'` 时，选中景点/餐厅会在 Agent 执行队列中插入 `dispatch_taxi` 调用，用户选择「豆柴院子咖啡馆」却触发了叫车 |
| 无法独立叫车 | 没有脱离 Agent 执行流程的独立叫车入口 |
| 首页无打车入口 | Home 页没有快捷打车的胶囊按钮 |
| 确认弹窗混乱 | Taxi 模式下的确认弹窗展示打车队列信息，与活动预订确认混在一起 |

### 用户决策

| 决策点 | 选择 |
|--------|------|
| 打车卡片交互形态 | **底部弹窗卡片**（与 CopilotPanel 相同的 spring 动画模式） |
| 首页打车目的地 | **同时支持两种**：有活跃行程时自动填充下一活动地点，无行程时手动输入 |
| Agent 集成方式 | **完全独立**，从 Agent 执行流程中移除所有 dispatch_taxi 步骤 |

### 范围
- ✅ 创建 TaxiBookingSheet 底部弹窗组件
- ✅ TravelSegmentCard 添加「去打车」按钮
- ✅ Home 页快捷服务添加「去打车」胶囊按钮
- ✅ 从 buildExecutionPlan 移除 dispatch_taxi 生成逻辑
- ✅ 从 Itinerary.tsx 移除 taxi 模式的确认弹窗/执行按钮特殊逻辑
- ✅ 从 Itinerary.tsx 移除 handleExecute 等函数中 dispatch_taxi 相关的成功判定
- ❌ 不改变 TravelMode 类型定义（`'taxi'` 依然是合法模式，路线规划复用驾车 API）
- ❌ 不改变 estimateTaxiDispatch 智能推荐算法
- ❌ 不涉及真实高德打车 API 对接（继续使用 dispatchTaxi 模拟工具）

在 Home.tsx 中处理「去打车」的点击：

```typescript
const handleQuickAction = useCallback((action: string) => {
  switch (action) {
    case 'weather':
      setServiceMode('weather');
      break;
    case 'restaurant':
      setServiceMode('restaurant');
      break;
    case 'delivery':
      setServiceMode('delivery');
      break;
    case 'activity':
      setServiceMode('ticket');
      break;
    case 'coupon':
      setServiceMode('coupon');
      break;
    case 'taxi':
      setTaxiSheetOpen(true);
      break;
  }
}, []);

**目的地自动填充逻辑**：
- 如果存在「活跃任务」（`activeTaskSession` 有值）且关联 plan 存在 → 取 plan 中第一个未完成的活动作为目的地
- 如果仅有当前 plan（`currentPlan` 存在）→ 取 plan 的第一个活动作为目的地
- 否则 → 目的地为空，用户手动输入

const handleTaxiOpen = useCallback(() => {
  const activePlan = currentPlan; // 从 context/store 获取
  const activeTaskSession = taskSessions.find(s => s.id === activeTaskSessionId);
  const plan = activeTaskSession?.planId 
    ? savedPlans.find(p => p.id === activeTaskSession.planId) 
    : currentPlan;

  if (plan && plan.activities.length > 0) {
    const firstActivity = plan.activities[0];
    setTaxiTarget({
      to: { name: firstActivity.title, lat: firstActivity.lat, lng: firstActivity.lng },
      activityTimeLine: firstActivity.timeLine,
    });
  }
  setTaxiSheetOpen(true);
}, [currentPlan, taskSessions, savedPlans]);
```

## 数据流设计

```
┌─────────────────────────────────────────────────────────────┐
│  场景 1: 行程页交通卡片点击「去打车」                          │
│                                                             │
│  User taps [去打车] on TravelSegmentCard                    │
│    → onBookTaxi(from, to) callback                         │
│    → setTaxiTarget({ from, to, activityTimeLine })         │
│    → setTaxiSheetOpen(true)                                │
│    → <TaxiBookingSheet> renders with pre-filled data       │
│    → User selects tier → taps [确认叫车]                    │
│    → dispatchTaxi({ from, to, tier, ... })                 │
│    → Show success Toast                                    │
│    → setTaxiSheetOpen(false)                               │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  场景 2: 首页点击「去打车」胶囊按钮                           │
│                                                             │
│  User taps [去打车] in QuickServiceShortcuts               │
│    → handleQuickAction('taxi')                             │
│    → Check active plan → auto-fill destination             │
│    → setTaxiSheetOpen(true)                                │
│    → <TaxiBookingSheet> renders                           │
│    → (if no plan) empty destination → user inputs manually │
│    → Same booking flow as above                            │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  场景 3: Agent 一键执行（打车已移除）                         │
│                                                             │
│  User selects activities → taps [一键执行预订]               │
│    → buildExecutionPlan(activities)                         │
│    → generates: calculate_route + search_restaurant +      │
│       check_availability + make_reservation                │
│    → NO dispatch_taxi calls                                │
│    → agentExecute runs → completes                         │
└─────────────────────────────────────────────────────────────┘
```

## 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| 移除 `dispatch_taxi` 后 Agent 执行逻辑出错 | 逐步移除，保留 taxi 类型的 tool handler 不变（仅移除调度逻辑） |
| TaxiBookingSheet 动画与其他 Sheet 冲突 | z-index 分层管理：Home Sheet z-50，Itinerary Sheet z-[60] |
| 自动定位失败时上车点为 null | 降级显示「正在定位...」→「无法定位，请手动输入」 |
| QuickServiceShortcuts 按钮过多（6个） | 使用当前已有的 5 个按钮相同样式，`min-w-max` 允许横向溢出滚动 |
